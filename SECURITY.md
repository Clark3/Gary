# Security Policy

## Reporting a vulnerability

Please do not disclose security vulnerabilities in public GitHub issues.

Use the repository's GitHub **Security / private vulnerability reporting** mechanism when available. Include enough detail to reproduce the issue, affected versions/commits, impact, and practical mitigation.

Do not include secrets, credentials, private keys, or personal data in the report.

## Scope

Security reports are especially important for privilege escalation paths, command-execution boundaries, approval-policy bypasses, secret leakage into portable state, unsafe repository synchronization, malicious model/tool interactions, unsafe Podman execution, and bootstrap supply-chain risks.
